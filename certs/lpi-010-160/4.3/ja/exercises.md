# 4.3 Where Data is Stored - ガイド付き演習

参考: https://learning.lpi.org/en/learning-materials/010-160/4/4.3/

この演習では、Linux の **Filesystem Hierarchy Standard (FHS)** に基づくディレクトリ構造と、`/proc` や `/sys` のような virtual filesystem、そして mount の基本を、実際にコマンドを実行しながら確認します。

---

## 演習1: ルートディレクトリの全体像を把握する

1. ターミナルを開き、ルートディレクトリの内容を一覧表示します。

   ```bash
   ls -l /
   ```

2. 表示された中から、以下のディレクトリを探してメモしてください:
   `/bin`, `/boot`, `/dev`, `/etc`, `/home`, `/lib`, `/media`, `/mnt`, `/opt`, `/proc`, `/root`, `/sbin`, `/srv`, `/sys`, `/tmp`, `/usr`, `/var`

3. `file /bin` を実行し、`/bin` がディレクトリなのか symbolic link なのかを確認します。

   ```bash
   file /bin /sbin /lib
   ```

**Q1.** このディレクトリ構造の並びと役割を規定している標準規格の名前は何ですか（英語表記のまま）？

**Q2.** 手順3の結果、多くの現代的なディストリビューションでは `/bin` が何を指す symbolic link になっていますか。この仕組みは一般に何と呼ばれていますか？

---

## 演習2: `/etc` に保存される設定情報を確認する

1. ディストリビューション情報を表示します。

   ```bash
   cat /etc/os-release
   ```

2. ユーザーアカウント情報を保持するファイルを閲覧します。

   ```bash
   cat /etc/passwd
   ```

3. `/etc` 直下のエントリ数を確認します。

   ```bash
   ls /etc | wc -l
   ```

**Q3.** `/etc` ディレクトリには一般的にどのような種類のファイルが置かれますか。

**Q4.** `/etc/passwd` に実際のパスワード（ハッシュ値）が保存されていない場合、代わりにどのファイルに保存されていますか。

---

## 演習3: `/var` に保存される可変データを確認する

1. ログディレクトリの内容を確認します。

   ```bash
   ls -l /var/log
   ```

2. システムログの末尾を表示します（環境によりファイル名が異なります）。

   ```bash
   sudo tail -n 20 /var/log/syslog
   ```
   または
   ```bash
   sudo journalctl -n 20
   ```

3. メールやキャッシュ、印刷キューなどのサブディレクトリも確認します。

   ```bash
   ls /var
   ```

**Q5.** `/etc` と `/var` の役割の違いを、それぞれに保存されるデータの性質から説明してください。

**Q6.** `/var/log` にはどのような情報が記録されますか。

---

## 演習4: `/home` と `/root` の違いを確認する

1. 現在ログインしているユーザーの home directory を確認します。

   ```bash
   echo $HOME
   ```

2. `/home` 配下の全ユーザーディレクトリを一覧表示します。

   ```bash
   ls -la /home
   ```

3. root ユーザーの home directory を確認します（権限が必要な場合があります）。

   ```bash
   sudo ls -la /root
   ```

**Q7.** 一般ユーザーの home directory と root ユーザーの home directory が、なぜ別の場所（`/home/username` と `/root`）に分かれているのか説明してください。

---

## 演習5: `/proc` - 仮想ファイルシステムを調べる

1. CPU 情報を表示します。

   ```bash
   cat /proc/cpuinfo | head -20
   ```

2. メモリ使用状況を表示します。

   ```bash
   cat /proc/meminfo | head -10
   ```

3. `/proc` のディスク上のサイズを確認します。

   ```bash
   du -sh /proc 2>/dev/null
   ```

4. 特定プロセス（例えば自分のシェル）の情報を確認します。

   ```bash
   echo $$
   ls /proc/$$
   ```

**Q8.** `/proc` は通常のディスク上のディレクトリとは性質が異なります。何が特別なのか説明してください。

**Q9.** 手順4で `/proc/<PID>` という形式のディレクトリが存在する理由は何ですか。

---

## 演習6: `/sys` - デバイスとカーネル情報を調べる

1. 認識されているデバイスクラスを一覧表示します。

   ```bash
   ls /sys/class
   ```

2. ネットワークインターフェースの情報を確認します。

   ```bash
   ls /sys/class/net
   cat /sys/class/net/*/address
   ```

**Q10.** `/proc` と `/sys` はどちらも virtual filesystem ですが、それぞれが主にどのような情報を提供するために設計されているか、役割の違いを説明してください。

---

## 演習7: mount とファイルシステムテーブルを確認する

1. 現在マウントされているファイルシステムを一覧表示します。

   ```bash
   mount | column -t
   ```

2. ディスク使用量と mount point を確認します。

   ```bash
   df -h
   ```

3. 起動時に自動マウントされる設定ファイルを閲覧します。

   ```bash
   cat /etc/fstab
   ```

4. （任意、権限があれば）USBメモリなど外部メディアを `/mnt` 配下に手動でマウントしてみます。

   ```bash
   sudo mkdir -p /mnt/usbtest
   sudo mount /dev/sdX1 /mnt/usbtest
   ```

**Q11.** `mount point` とは何ですか。

**Q12.** `/etc/fstab` の役割を説明してください。手動で `mount` コマンドを実行するのと何が違いますか。

**Q13.** `/mnt` と `/media` はどちらも外部ストレージ用のディレクトリですが、慣習的にどのように使い分けられますか。

---

<details>
<summary>解答</summary>

**Q1.** Filesystem Hierarchy Standard (FHS)。Linux ディストリビューション間でディレクトリの配置や用途に一貫性を持たせるための標準規格です。

**Q2.** `/bin` は多くの場合 `/usr/bin` への symbolic link になっています。この統合は **usr-merge** と呼ばれ、`/bin`、`/sbin`、`/lib` をそれぞれ `/usr` 配下に統合することで、ルートファイルシステムと `/usr` を分離する必要性をなくし、管理を簡素化する目的で行われています。

**Q3.** システム全体やインストールされているアプリケーションの設定ファイル（configuration files）です。基本的にプレーンテキストで、実行可能ファイルやユーザーデータは含まれません。

**Q4.** `/etc/shadow`。パスワードのハッシュ値はここに保存され、root 以外は読み取れないよう権限が制限されています。

**Q5.** `/etc` は変化の少ない静的な設定情報（configuration）を保存する場所であるのに対し、`/var` はログファイル、メールスプール、キャッシュ、印刷キューなど、システム稼働中に頻繁に変化する可変データ（variable data）を保存する場所です。

**Q6.** カーネルメッセージ、認証記録、各種デーモンやアプリケーションが出力する動作ログなど、システムの稼働状況を記録した情報です。

**Q7.** root は他の一般ユーザーとは異なる特権を持つ管理アカウントであり、`/home` がまだマウントされていない起動初期段階（例えばシングルユーザーモードやレスキュー作業時）でも root がログインしてシステムを操作できるよう、home directory をルートファイルシステム直下の `/root` に置くことで `/home` パーティションへの依存をなくしています。

**Q8.** `/proc` はディスク上に実体を持たない virtual filesystem（pseudo-filesystem）です。ここにあるファイルはカーネルがメモリ上で動的に生成する情報の窓口であり、`du` で見てもディスク容量をほぼ消費しません。

**Q9.** 実行中の各プロセスのプロセスID (PID) ごとに、そのプロセスの状態、メモリマップ、開いているファイルディスクリプタなどをカーネルが動的に公開しているためです。

**Q10.** `/proc` は主に実行中のプロセスやカーネルのランタイム状態（CPU、メモリ、プロセス情報など）を公開するのに対し、`/sys` はカーネルが認識しているデバイスやドライバ、バスといったハードウェア構成とカーネルオブジェクトの階層構造を公開するために設計されています。

**Q11.** ファイルシステムをアクセス可能にするために接続（mount）する先のディレクトリのことです。mount 後は、そのディレクトリ配下にアクセスすることで、接続されたファイルシステムの内容を読み書きできます。

**Q12.** `/etc/fstab` はシステム起動時に自動的にマウントすべきファイルシステムの一覧（デバイス、mount point、ファイルシステム種別、オプションなど）を定義した設定ファイルです。手動で `mount` コマンドを実行する場合は現在のセッションのみ一時的に有効ですが、`/etc/fstab` に記載すれば再起動後も自動的に同じ構成でマウントされます。

**Q13.** 慣習として `/mnt` は管理者が一時的に手動でマウントする際に使う汎用的な場所であり、`/media` は USB メモリや DVD など、リムーバブルメディアが自動マウントされる際に使われることが多い場所です。

</details>
