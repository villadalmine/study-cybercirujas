# 4.3 Where Data is Stored

**Exam:** LPI Linux Essentials 010-160 (version 1.6) — **Weight: 3**

---

## Overview

Linux follows the philosophy that *everything is a file* — programs, configuration, logs, and even the kernel's view of hardware and running processes are exposed through the filesystem. This topic covers **where** the different kinds of data live on a Linux system and **which tools** you use to inspect them:

- Programs and their configuration
- Processes and process information (`ps`, `top`, `/proc`)
- Memory usage and memory addresses (`free`)
- The kernel, device files, and pseudo-filesystems (`/boot`, `/dev`, `/proc`, `/sys`)
- System messaging and logging (`dmesg`, syslog, `systemd-journald`)
- Querying hardware (`dmidecode`)

---

## 1. Programs and Configuration

### Where programs live

Executable programs are spread across a few standard directories defined by the **Filesystem Hierarchy Standard (FHS)**:

| Directory | Purpose |
|---|---|
| `/bin`, `/usr/bin` | Essential and general user commands (`ls`, `cp`, `bash`) |
| `/sbin`, `/usr/sbin` | System administration commands (`fdisk`, `mkfs`), usually run by root |
| `/usr/local/bin` | Programs installed manually by the administrator (outside the package manager) |
| `/opt` | Self-contained third-party application bundles |

On many modern distributions `/bin` and `/sbin` are symbolic links to their `/usr` counterparts (the "usrmerge" layout):

```
$ ls -ld /bin /sbin
lrwxrwxrwx. 1 root root 7 Aug  9  2025 /bin -> usr/bin
lrwxrwxrwx. 1 root root 8 Aug  9  2025 /sbin -> usr/sbin
```

Use `which` to find where a command is located:

```
$ which passwd
/usr/bin/passwd
```

### Where configuration lives

- **System-wide configuration** is stored in **`/etc`** as plain text files. Examples: `/etc/passwd` (user accounts), `/etc/hosts` (static hostname resolution), `/etc/fstab` (filesystems to mount at boot), `/etc/ssh/sshd_config` (SSH server settings).
- **Per-user configuration** is stored in the user's **home directory**, usually as *hidden* files or directories whose names start with a dot (hence "dotfiles"): `~/.bashrc`, `~/.ssh/`, `~/.config/`.

```
$ ls -a ~ | head -6
.
..
.bash_history
.bashrc
.config
.ssh
```

Keeping configuration in plain text files is a key Linux trait: it can be read, edited, versioned, and backed up with ordinary tools.

### Packages and package databases

Software is normally installed via a **package manager**, which keeps a **database** of every installed package and the files it owns:

- **Debian/Ubuntu**: `dpkg`/`apt`, database under `/var/lib/dpkg`
- **RHEL/Fedora/SUSE**: `rpm`/`dnf`/`zypper`, database under `/var/lib/rpm`

```
$ dpkg -S /usr/bin/passwd        # Debian: which package owns this file?
passwd: /usr/bin/passwd

$ rpm -qf /usr/bin/passwd        # RPM-based equivalent
passwd-0.80-14.fc40.x86_64
```

Downloaded package files and other variable cache data live under `/var/cache` (e.g. `/var/cache/apt/archives`).

## 2. Processes

A **process** is a running instance of a program. Every process has a unique **PID** (Process ID) and a **PPID** (Parent Process ID — the process that started it). The first process started by the kernel (PID 1, usually `systemd`) is the ancestor of all others, forming a tree.

### `ps` — snapshot of processes

```
$ ps aux | head -4
USER  PID %CPU %MEM    VSZ   RSS TTY   STAT START  TIME COMMAND
root    1  0.0  0.3 169936 13100 ?     Ss   09:12  0:02 /usr/lib/systemd/systemd
root    2  0.0  0.0      0     0 ?     S    09:12  0:00 [kthreadd]
dal  1420  0.1  1.2 823416 49212 pts/0 Sl   09:15  0:04 /usr/bin/bash
```

Common option styles (both widely used):

- `ps aux` — BSD style: **a**ll users, with **u**ser info, including processes with no terminal (**x**)
- `ps -ef` — UNIX style: **e**very process, **f**ull format (shows PPID)

Key columns: `PID`, `%CPU`, `%MEM`, `VSZ` (virtual memory), `RSS` (resident/physical memory), `STAT` (process state), `COMMAND`.

### `top` — live, interactive view

`top` refreshes every few seconds and sorts by CPU usage by default:

```
$ top
top - 10:31:07 up  1:18,  1 user,  load average: 0.15, 0.20, 0.18
Tasks: 213 total,   1 running, 212 sleeping,   0 stopped,   0 zombie
%Cpu(s):  2.3 us,  0.7 sy,  0.0 ni, 96.8 id,  0.1 wa,  0.0 hi,  0.1 si
MiB Mem :   7842.4 total,   3210.9 free,   2110.2 used,   2521.3 buff/cache
MiB Swap:   2048.0 total,   2048.0 free,      0.0 used.   5401.7 avail Mem
```

Useful interactive keys: `M` (sort by memory), `P` (sort by CPU), `k` (kill a process), `q` (quit). Many systems also ship `htop`, a friendlier alternative.

### `/proc` — the process pseudo-filesystem

`/proc` is a **virtual (pseudo) filesystem**: its files exist only in memory and are generated by the kernel on the fly. Each running process has a numbered directory `/proc/<PID>` containing its details:

```
$ ls /proc/1420
cmdline  cwd  environ  exe  fd  limits  maps  status ...

$ cat /proc/1420/cmdline
/usr/bin/bash
```

Notable entries inside `/proc/<PID>`:

- `cmdline` — the command line that started the process
- `cwd` — symlink to its current working directory
- `environ` — its environment variables
- `status` — human-readable state, memory usage, UID/GID

`/proc` also exposes **system-wide** kernel information (not tied to one process):

```
$ cat /proc/cpuinfo | grep "model name" | head -1
model name : Intel(R) Core(TM) i7-1165G7 @ 2.80GHz

$ grep MemTotal /proc/meminfo
MemTotal:        8030616 kB
```

Other frequently used files: `/proc/version` (kernel version), `/proc/cmdline` (kernel boot parameters), `/proc/mounts` (mounted filesystems). Tools like `ps`, `top` and `free` actually read their data from `/proc`.

## 3. Memory

### Physical memory, virtual memory, and swap

Each process sees its own private range of **virtual memory addresses**; the kernel maps these onto physical RAM. When RAM runs low, the kernel can move inactive pages to **swap** space on disk (a swap partition or swap file). Swap is much slower than RAM — heavy, sustained swap usage is a sign the system needs more memory.

### `free` — memory usage summary

```
$ free -h
               total        used        free      shared  buff/cache   available
Mem:           7.7Gi       2.1Gi       3.1Gi       310Mi       2.5Gi       5.3Gi
Swap:          2.0Gi          0B       2.0Gi
```

- `-h` prints human-readable units (`-m` for MiB, `-g` for GiB)
- **buff/cache**: RAM the kernel uses to cache disk data. This memory is *not wasted* — it is released automatically when applications need it.
- **available** is the best estimate of memory that new applications can actually use (free + reclaimable cache). Don't panic over a small `free` value; look at `available`.

You can see the same data raw in `/proc/meminfo`, and swap devices in `/proc/swaps`.

## 4. The Kernel, `/boot`, `/dev`, and `/sys`

### `/boot` — kernel and boot files

The Linux **kernel** image and the files needed to boot live in `/boot`:

```
$ ls /boot
config-6.8.0-45-generic  grub  initrd.img-6.8.0-45-generic  vmlinuz-6.8.0-45-generic
```

- `vmlinuz-*` — the compressed kernel image
- `initrd.img-*` / `initramfs-*` — initial RAM disk with drivers needed early in boot
- `grub/` — bootloader configuration
- `config-*` — the options the kernel was built with

Check the running kernel version with:

```
$ uname -r
6.8.0-45-generic
```

### `/dev` — device files

Hardware devices are represented as **device files** in `/dev`, so programs can talk to devices using normal file operations:

```
$ ls -l /dev/sda /dev/tty1 /dev/null
brw-rw----. 1 root disk 8, 0 Jul  7 09:12 /dev/sda
crw--w----. 1 root tty  4, 1 Jul  7 09:12 /dev/tty1
crw-rw-rw-. 1 root root 1, 3 Jul  7 09:12 /dev/null
```

- **Block devices** (`b`): transfer data in blocks — disks and partitions (`/dev/sda`, `/dev/sda1`, `/dev/nvme0n1`, `/dev/mmcblk0`)
- **Character devices** (`c`): transfer data as byte streams — terminals, `/dev/null`

Special pseudo-devices worth knowing:

- `/dev/null` — discards everything written to it ("bit bucket"): `command 2> /dev/null`
- `/dev/zero` — endless stream of zero bytes
- `/dev/random`, `/dev/urandom` — random data

`/dev` is managed dynamically by `udev`, so device files appear and disappear as hardware is plugged in or removed.

### `/sys` — the sysfs pseudo-filesystem

Like `/proc`, **`/sys`** is a virtual filesystem, but it is dedicated to a structured view of **devices, drivers, and kernel subsystems**:

```
$ ls /sys
block  bus  class  dev  devices  firmware  fs  kernel  module  power

$ cat /sys/class/net/eth0/address
52:54:00:ab:cd:12
```

Rule of thumb for the exam: **`/proc` = processes + kernel runtime info; `/sys` = hardware/device information; `/dev` = the device files themselves.**

## 5. System Messaging and Logging

### `dmesg` — the kernel ring buffer

The kernel writes its own messages (hardware detection, drivers, errors) to an in-memory **ring buffer** (old messages are overwritten as it fills). View it with `dmesg` (often requires root):

```
$ sudo dmesg | tail -3
[ 1024.301] usb 2-1: new SuperSpeed USB device number 3 using xhci_hcd
[ 1024.322] usb-storage 2-1:1.0: USB Mass Storage device detected
[ 1025.351] sd 6:0:0:0: [sdb] Attached SCSI removable disk
```

`dmesg -H` gives paginated, human-readable timestamps. On systemd systems, `journalctl -k` shows the same kernel messages.

### Syslog and `/var/log`

Traditionally, a **syslog** daemon (`rsyslog` on most distributions) collects messages from the kernel and from services and writes them to plain-text files under **`/var/log`**. Messages are classified by **facility** (what produced it: `kern`, `mail`, `auth`, `cron`, …) and **severity** (from `debug` up to `emerg`).

Common log files (names vary by distribution):

| File | Content |
|---|---|
| `/var/log/syslog` (Debian) / `/var/log/messages` (RHEL) | General system messages |
| `/var/log/auth.log` / `/var/log/secure` | Authentication, logins, `sudo` |
| `/var/log/kern.log` | Kernel messages |
| `/var/log/boot.log` | Boot-time service output |

```
$ sudo tail -2 /var/log/auth.log
Jul  7 10:02:11 host sshd[2311]: Accepted publickey for dal from 192.168.1.20 port 51234
Jul  7 10:05:47 host sudo:   dal : TTY=pts/0 ; COMMAND=/usr/bin/dmesg
```

To prevent logs from filling the disk, **`logrotate`** periodically renames, compresses, and eventually deletes old log files (e.g. `syslog` → `syslog.1` → `syslog.2.gz`), driven by `/etc/logrotate.conf` and `/etc/logrotate.d/`.

### The systemd journal — `journalctl`

On systemd-based systems, **`systemd-journald`** collects all logs into a structured, **binary** journal (so you must use `journalctl` to read it, not `cat`). It can work alongside or instead of rsyslog.

```
$ journalctl -u ssh --since "1 hour ago"
Jul 07 10:02:11 host sshd[2311]: Accepted publickey for dal from 192.168.1.20
```

Useful options:

- `journalctl -b` — messages from the current boot
- `journalctl -k` — kernel messages only (like `dmesg`)
- `journalctl -u <unit>` — messages from one service
- `journalctl -f` — follow new messages live (like `tail -f`)

The journal is stored in `/run/log/journal` (volatile, lost on reboot) or `/var/log/journal` (persistent, if that directory exists).

## 6. Querying Hardware: `dmidecode`

**`dmidecode`** reads the **DMI/SMBIOS** tables provided by the system firmware and reports hardware details — manufacturer, model, BIOS version, memory slots, serial numbers — without opening the case. It requires root:

```
$ sudo dmidecode -t system | head -8
# dmidecode 3.5
Getting SMBIOS data from sysfs.
SMBIOS 3.2 present.

Handle 0x0001, DMI type 1, 27 bytes
System Information
        Manufacturer: LENOVO
        Product Name: 20XW004GUS
```

Handy type filters: `dmidecode -t bios`, `-t system`, `-t memory`, `-t processor`.

```
$ sudo dmidecode -t memory | grep -E "Size|Speed" | head -4
        Size: 8 GB
        Speed: 3200 MT/s
        Size: No Module Installed
```

Note: DMI data comes from the motherboard firmware, so it is typically unavailable or meaningless inside virtual machines and on architectures without SMBIOS (e.g. many ARM boards).

## Quick Reference

| I want to see… | Command / Location |
|---|---|
| Running processes (snapshot / live) | `ps aux`, `ps -ef` / `top` |
| Memory and swap usage | `free -h`, `/proc/meminfo` |
| Kernel and process runtime info | `/proc` (`cpuinfo`, `meminfo`, `/proc/<PID>/`) |
| Device/driver info from the kernel | `/sys` |
| Device files | `/dev` (block `b` vs character `c`) |
| Kernel image and boot files | `/boot` (`vmlinuz-*`, `initrd.img-*`) |
| Kernel boot/hardware messages | `dmesg`, `journalctl -k` |
| Service and system logs | `/var/log/*`, `journalctl` |
| System-wide vs per-user configuration | `/etc` vs dotfiles in `~` |
| Hardware inventory from firmware | `sudo dmidecode` |
