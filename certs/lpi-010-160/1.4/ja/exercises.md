> **前提条件:** desktop environment 付きの Linux 環境（物理マシンまたは仮想マシン）と Web ブラウザ。特に指定がない限り管理者権限は不要です。

## 演習 1 — desktop からコマンドラインへ到達する

Linux での作業の多くは **command line** 上で行われます。まずはグラフィカルな環境からそこへたどり着く方法を確認します。

1. お使いの desktop environment（GNOME、KDE Plasma、Xfce など）にログインします。
2. アプリケーションランチャーを開き、**terminal** というキーワードで検索します。desktop environment によってアプリケーション名は異なります（例: *GNOME Terminal*、*Konsole*、*Xfce Terminal*）。
3. アプリケーションを起動します。次のような **prompt** が表示されるはずです。
   ```
   user@mainbox:~$
   ```
4. 次のコマンドを入力して Enter を押します。
   ```
   echo "Hello from the shell"
   ```
5. 現在使っている **shell** を確認します。
   ```
   echo $SHELL
   ```
6. 次のコマンドでターミナルを終了します。
   ```
   exit
   ```

**確認問題:**

- **1.a** *terminal emulator* と *shell* の違いを説明してください。
- **1.b** prompt 末尾の `$` は何を意味しますか。`#` の場合はどうですか。
- **1.c** 多くの Linux ディストリビューションで既定になっている shell は何ですか。

## 演習 2 — Virtual console を使う

Linux には desktop environment とは独立したテキストベースの **virtual console** が複数用意されています。GUI が動かないときやデスクトップのないサーバーで役立ちます。

> ⚠️ 仮想マシン上で作業している場合、キーボードショートカットがホスト OS に奪われることがあります。VirtualBox の場合は `Ctrl+Alt` の代わりに *Host* キーを使ってください。

1. グラフィカルなセッションから `Ctrl+Alt+F3` を押します。次のようなログインメッセージが表示されるテキスト画面が出るはずです。
   ```
   mainbox login:
   ```
2. ユーザー名とパスワードを入力します。**入力中パスワードが画面に表示されない**のは正常な動作です。
3. セッションが機能していることを確認するために何かコマンドを実行します。
   ```
   who
   ```
   自分のセッションが `tty` として表示されることを確認します。
4. コンソールのセッションを終了します。
   ```
   exit
   ```
5. `Ctrl+Alt+F1` または `Ctrl+Alt+F2` を試して、grapical セッションに戻ります（グラフィカルセッションが動いている正確な console 番号はディストリビューションによって異なります）。

**確認問題:**

- **2.a** desktop の terminal emulator ではなく virtual console を使うべき具体的な場面はどのような時ですか。
- **2.b** `who` コマンドは何を表示し、何のために使いますか。
- **2.c** console でパスワードを入力しても画面に表示されないのはなぜですか。

## 演習 3 — 強力なパスワードを設定する

パスワードはアカウントを守る最初の防衛線です。この演習ではパスワードを変更し、何が強いパスワードを作るかを考えます。

1. ターミナルを開きます。
2. パスワードを変更するコマンドを実行します。
   ```
   passwd
   ```
3. 求められたら現在のパスワードを入力します。
4. 次の条件を満たす新しいパスワードを入力します: 最低12文字、大文字・小文字・数字・記号を組み合わせる、辞書に載っている単語や個人情報（誕生日、ペットの名前など）を含まない。
5. 意図的に短すぎるパスワード（例: `abc`）を入力してみて、システムが拒否するメッセージを観察します。
6. 強いパスワードで手順をやり直し、2回入力して確定します。

**確認問題:**

- **3.a** 強いパスワードの特徴を3つ挙げてください。
- **3.b** 複数のサービスで同じパスワードを使い回すのがなぜ良くない習慣なのか説明してください。
- **3.c** 多数の異なるパスワードを覚えずに管理するのに役立つソフトウェアは何ですか。

## 演習 4 — Web ブラウザでのプライバシー

ブラウザは **cookie**、閲覧履歴、キャッシュファイルを保存しており、これらはあなたの閲覧習慣を明らかにする可能性があります。ここではそのデータを確認し、削除します。

1. **Firefox**（またはお使いのシステムにインストールされているブラウザ）を開きます。
2. 任意のサイトを2〜3個訪問します。
3. 閲覧履歴を開きます（Firefox の場合: メニュー ☰ → *History*）。訪問したサイトが記録されていることを確認します。
4. プライバシー設定に入ります（Firefox の場合: メニュー ☰ → *Settings* → *Privacy & Security*）。
5. **cookies and site data** のセクションを探し、保存されているデータがどれくらいの容量を占めているか確認します。
6. 最近の履歴と cookie を削除します（Firefox の場合: *Clear Data* / *Clear History*）。
7. 次に **private browsing（プライベートブラウジング）** ウィンドウを開き（Firefox では `Ctrl+Shift+P`）、サイトを訪問してからウィンドウを閉じ、その訪問が履歴に**記録されていない**ことを確認します。

**確認問題:**

- **4.a** cookie とは何であり、Web サイトは何のためにそれを使いますか。
- **4.b** private browsing モードは、訪問しているサイトやインターネットプロバイダーに対してあなたを匿名にしますか。理由も述べてください。
- **4.c** プライバシーの観点で、first-party cookie と third-party cookie の違いは何ですか。

## 演習 5 — 画面ロックと暗号化

セッションとローカルデータを保護することもセキュリティの良い習慣の一部です。

1. グラフィカルセッションが開いた状態で、desktop environment のショートカットで画面をロックします（GNOME の場合: `Super+L`）。
2. 再度ログインする際にパスワードを求められることを確認します。
3. ターミナルを開き、暗号化ツールが利用可能か確認します。
   ```
   which gpg
   ```
4. テストファイルを作成し、**GnuPG** で対称暗号化します。
   ```
   echo "confidential data" > secret.txt
   gpg -c secret.txt
   ```
   求められたら **passphrase** を入力します。
5. ファイル一覧を表示し、`secret.txt.gpg` が作成されたことを確認します。
   ```
   ls -l secret*
   ```
6. 元のファイルを削除し、保護されたコピーを復号して内容を復元します。
   ```
   rm secret.txt
   gpg -d secret.txt.gpg
   ```
7. テストファイルを片付けます。
   ```
   rm secret.txt.gpg
   ```

**確認問題:**

- **5.a** 「ほんの1分」席を離れるだけでも画面をロックすべきなのはなぜですか。
- **5.b** ファイルを暗号化することと、ユーザー権限だけで保護することの概念的な違いは何ですか。
- **5.c** ファイル暗号化以外に、電源を切ったノートパソコンが盗まれた場合でもデータを守る暗号化の方式は何ですか。

## 演習 6 — 日常業務のためのオープンソースアプリケーション

Linux には、よく使われるプロプライエタリなツールに相当するオープンソースアプリケーションが用意されています。この演習ではそれらを確認し、実際に1つ使ってみます。

1. アプリケーションランチャーを開き、次の各作業にどのプログラムがインストールされているか書き出します。
   - Web ブラウジング
   - 文書作成
   - 表計算
   - プレゼンテーション
   - 画像編集
2. **LibreOffice Impress** を開きます（インストールされていない場合はディストリビューションのソフトウェアマネージャーからインストールします）。
3. タイトルを *"Linux in Industry"* とする、1枚だけのスライドの新規プレゼンテーションを作成します。
4. Linux が優位な領域を3つ挙げたリストを追加します: **servers and cloud computing**、**supercomputers**、**embedded devices / Android**。
5. ファイルをネイティブ形式（`.odp`）で保存し、その後 **PDF** としてもエクスポートします（*File → Export As → Export as PDF*）。
6. ターミナルから両方のファイルが存在することを確認します。
   ```
   ls -l ~/*.odp ~/*.pdf
   ```

**確認問題:**

- **6.a** 次の対応表を埋めてください。

  | 作業 | 代表的なプロプライエタリアプリケーション | オープンソースの代替 |
  |---|---|---|
  | 表計算 | Microsoft Excel | ? |
  | 画像編集 | Adobe Photoshop | ? |
  | プレゼンテーション | Microsoft PowerPoint | ? |

- **6.b** LibreOffice がネイティブに使用するファイル形式は何ですか。それがオープンな標準であることにはどんな利点がありますか。
- **6.c** 他の OS を使っている相手と共有するプレゼンテーションを PDF にエクスポートする利点は何ですか。

## 演習 7 — Linux とクラウド・仮想化（概念的な調査）

この演習は調査型で、何もインストールする必要はありません。

1. ターミナルから、自分のシステムが仮想マシン上で動いているかどうかを確認します。
   ```
   systemd-detect-virt
   ```
   `none` が返れば物理ハードウェア上、`kvm`、`oracle`、`vmware` などが返れば VM 上で動作しています。
2. 主要な cloud provider（AWS、Google Cloud、Azure）のサーバーで大半を占める OS について、Web で5〜10分ほど調べます。
3. **Android** の kernel が何であるか調べます。
4. 日常的に使っているが Linux が動いていると気づきにくいデバイスやサービスの例を3つ、テキストファイルに書き出します。
   ```
   nano hidden-linux.txt
   ```
   （`Ctrl+O` で保存、`Ctrl+X` で終了）。

**確認問題:**

- **7.a** virtual machine とは何であり、専用ハードウェアに各システムを個別にインストールするのと比べてどんな利点がありますか。
- **7.b** Linux と *cloud computing* の関係を説明してください。
- **7.c** Linux が動いていることが一般的な組み込みデバイスの種類を3つ挙げてください。

---

<details>
<summary><strong>✅ 解答</strong></summary>

### 演習 1

- **1.a** *terminal emulator* は、入力するウィンドウを表示するグラフィカルなアプリケーションです（GNOME Terminal、Konsole など）。*shell* はそのウィンドウの内部で動作し、入力されたコマンドを解釈して結果を返すプログラムです（例: Bash）。terminal は「窓」、shell は「解釈者」に相当します。
- **1.b** `$` は一般ユーザー（権限のないアカウント）のセッションであることを示します。`#` は **root** ユーザー（管理者）のセッションであることを示すため、より慎重に操作する必要があります。
- **1.c** **Bash**（Bourne Again Shell）が、ほとんどのディストリビューションで既定の shell です。

### 演習 2

- **2.a** グラフィカルな環境がフリーズしたり起動しなかったりする場合、または desktop のないサーバーを管理する場合に有用です。virtual console はグラフィカルセッションとは独立して動作します。
- **2.b** `who` はシステムにログイン中のユーザーを、接続元の terminal（`tty`）とログイン時刻とともに表示します。誰がシステムを使用しているかを監査するのに使います。
- **2.c** セキュリティ上の対策です。画面を覗き見（*shoulder surfing*）している人にパスワードやその長さが見えないようにするためです。

### 演習 3

- **3.a** 十分な長さ（12文字以上）、複数種類の文字（大文字・小文字・数字・記号）の組み合わせ、そして予測不能であること（辞書の単語、個人情報、キーボードのパターンを避ける）。さらに各サービスごとにユニークであることも重要です。
- **3.b** あるサービスで情報漏えいが起きると、攻撃者は同じユーザー名/パスワードの組み合わせを他のサービスでも試します（**credential stuffing**）。1回の漏えいですべてのアカウントが危険にさらされます。
- **3.c** **password manager**（パスワードマネージャー）です。KeePassXC や Bitwarden などがあり、ユニークで強力なパスワードを生成・保存してくれるため、覚える必要があるのはマスターパスワードだけです。

### 演習 4

- **4.a** cookie は Web サイトがブラウザに保存する小さなデータです。ログインセッションの維持や設定の記憶といった正当な目的で使われる一方、広告目的であなたの行動を追跡するためにも使われます。
- **4.b** いいえ。private browsing モードは、ブラウザがローカルに履歴・cookie・フォームデータを保存しないようにするだけです。訪問先の Web サイトは引き続きあなたの IP アドレスを見ることができ、インターネットプロバイダーも訪問先サイトを把握できます。
- **4.c** **first-party cookie** は訪問しているサイト自身が発行するもので、通常は機能的な目的に使われます。**third-party cookie** はページに埋め込まれた別のドメイン（広告ネットワークやソーシャルボタンなど）が発行するもので、複数サイトをまたいだ閲覧行動の追跡を可能にするため、プライバシー上より問題視されます。

### 演習 5

- **5.a** ほんの一瞬でも物理的にアクセスできる人がいれば、データを読んだり、あなたになりすましてメッセージを送ったり、悪意あるソフトウェアをインストールしたりできるからです。画面ロックは、セッションを再開する際にパスワードを要求します。
- **5.b** ユーザー権限は OS が強制するものです。誰かがディスクを取り外して別のシステムから読み取ったり、live USB で起動したりすると、権限は無効化されます。暗号化はコンテンツを数学的に保護するもので、鍵や passphrase がなければディスクに直接アクセスしてもデータは判読できません。
- **5.c** **full disk encryption**（例: LUKS）です。多くの場合ディストリビューションのインストール時に設定します。passphrase がなければディスクの内容にアクセスできません。

### 演習 6

- **6.a**

  | 作業 | 代表的なプロプライエタリアプリケーション | オープンソースの代替 |
  |---|---|---|
  | 表計算 | Microsoft Excel | **LibreOffice Calc** |
  | 画像編集 | Adobe Photoshop | **GIMP** |
  | プレゼンテーション | Microsoft PowerPoint | **LibreOffice Impress** |

- **6.b** **OpenDocument Format（ODF）**です。文書には `.odt`、表計算には `.ods`、プレゼンテーションには `.odp` を使います。オープンな標準であるため、どのソフトウェアでも実装可能であり、特定のベンダーに依存せずに将来もファイルを読み込み続けられることが保証されます。
- **6.c** PDF はどの OS 上でもレイアウト（フォント、配置）を正確に保持し、受信者が LibreOffice や PowerPoint を持っていなくても、どのプラットフォームでも無料のビューアで開くことができます。

### 演習 7

- **7.a** virtual machine とは、物理マシンの中でソフトウェアによってシミュレートされる、独自の OS を持つコンピューターです。利点としては、複数のシステムが同じハードウェア上で共存できること、リソースをより効率的に活用できること、VM を数分で作成・複製・破棄できることが挙げられます。
- **7.b** Linux は cloud computing で支配的な OS です。AWS、Google Cloud、Azure のサーバーインスタンスの大半は Linux 上で動作しており、クラウドの virtualization やコンテナのインフラ（KVM、Docker、Kubernetes）の多くも Linux の上に構築されています。
- **7.c** ルーターやネットワーク機器、smart TV、そして **Android**（kernel は Linux）を搭載したスマートフォンです。カーナビ・車載エンターテインメントシステム、カメラ、IoT デバイス、電子書籍リーダーなども正解として有効です。

</details>
