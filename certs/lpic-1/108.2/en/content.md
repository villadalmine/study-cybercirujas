# 108.2 System Logging

**LPIC-1 · Exam 102-500 · Version 5.0**
*Advanced SRE / Platform Architect profile*

> Scope note: this objective covers the classic syslog data model, `rsyslog` configuration, the systemd journal (`systemd-journald` / `journalctl`), the `logger` and `systemd-cat` message injectors, and `logrotate`. The material below treats them as one production subsystem rather than as four unrelated commands, because in a real fleet they are one subsystem.

---

## 1. Motivation: the architectural problem logging actually solves

A Linux host produces diagnostic events from four structurally different producers, and none of them share a transport by accident:

| Producer | Native sink | Mechanism |
|---|---|---|
| Kernel (`printk`) | Ring buffer | `/dev/kmsg`, `/proc/kmsg`, read by `dmesg`, `systemd-journald`, or `imklog` |
| Services started by systemd | Journal | `stdout`/`stderr` are pipes owned by `journald` (`StandardOutput=journal`) |
| Legacy/daemonised processes | `/dev/log` | `AF_UNIX` `SOCK_DGRAM` socket, RFC 3164 payload |
| Applications writing files directly | Own file | `nginx`, `mysqld`, `httpd` — nobody's socket, hence `logrotate` |

The architectural problem is not "where do I read logs". It is:

1. **Loss under pressure.** A datagram socket drops silently. A UDP forwarder drops silently. A full disk causes `journald` to stop storing, and a naive `rsyslog` action blocks its whole ruleset. Each of these is a *different* failure with a *different* mitigation, and the default configuration of every distribution chooses "drop quietly" over "block the producer" — the correct default for availability, the wrong default for forensics.
2. **Local storage is not durable storage.** The host that logs the incident is frequently the host that is about to disappear (spot instance, OOM, kernel panic, `terraform destroy`). Any log that only ever existed on the failing node is worth roughly nothing at post-mortem time. This is why "configure the syslog daemon" in an exam objective becomes "configure a guaranteed-delivery relay chain with disk-assisted queues" in production.
3. **Unbounded growth is an outage class of its own.** `/var` filling up takes down the machine far more often than any application bug. `logrotate` and `journald`'s `SystemMaxUse=` are not housekeeping; they are the guardrails that keep the logging subsystem from becoming the incident.
4. **Structure loss.** RFC 3164 collapses everything into a free-text string. The journal keeps typed key/value fields (`_PID`, `_SYSTEMD_UNIT`, `_UID`, `MESSAGE_ID`) but is host-local and binary. Anything that crosses the network in classic syslog format loses the structure that made the local query useful. Choosing where you pay that tax is the central design decision of this topic.

A production logging pipeline is therefore always three tiers: **collect** (journald / rsyslog inputs) → **buffer + relay** (queues, RELP/TLS) → **retain** (rotation locally, object store or index centrally). LPIC-1 tests tier 1 and the local half of tier 3; a Platform Architect owns all three.

## 2. The syslog data model

### 2.1 Facility and severity

Every classic syslog message carries a **PRI** value computed as:

```
PRI = (facility × 8) + severity
```

**Facilities** (RFC 5424 §6.2.1):

| Code | Keyword | Typical producer |
|---|---|---|
| 0 | `kern` | Kernel messages (cannot be generated by userspace on most kernels) |
| 1 | `user` | Generic userspace — **default for `logger`** |
| 2 | `mail` | MTA (postfix, exim) |
| 3 | `daemon` | System daemons without a dedicated facility |
| 4 | `auth` | Authentication/authorization (`login`, `su`) |
| 5 | `syslog` | The syslog daemon itself |
| 6 | `lpr` | Line printer subsystem |
| 7 | `news` | NNTP |
| 8 | `uucp` | UUCP |
| 9 | `cron` | `cron`/`at` |
| 10 | `authpriv` | Auth messages containing private data — **`sshd`, `sudo`, PAM** |
| 11 | `ftp` | FTP daemon |
| 12 | `ntp` | NTP subsystem |
| 13 | — | Log audit |
| 14 | — | Log alert |
| 15 | `clock` | Clock daemon |
| 16–23 | `local0`–`local7` | Site-defined — **the only correct place for your own applications** |

**Severities** (RFC 5424 §6.2.1), lowest number = most severe:

| Code | Keyword | Meaning | SRE reading |
|---|---|---|---|
| 0 | `emerg` (`panic`) | System unusable | Page immediately |
| 1 | `alert` | Action required immediately | Page immediately |
| 2 | `crit` | Critical condition | Page |
| 3 | `err` (`error`) | Error condition | Ticket / alert on rate |
| 4 | `warning` (`warn`) | Warning | Rate-based alert only |
| 5 | `notice` | Normal but significant | Retain, do not alert |
| 6 | `info` | Informational | Retain, sample |
| 7 | `debug` | Debug-level | Off in production; enable per-unit |

> **Exam trap:** the deprecated keywords `error`, `warn` and `panic` are accepted by rsyslog but should not be written in new configuration. `authpriv` — not `auth` — is where `sshd` and `sudo` land on virtually every modern distribution.

Worked example: an `authpriv` (10) message at `err` (3) severity carries `PRI = 10×8 + 3 = 83`, transmitted as `<83>`.

### 2.2 Wire formats

| Aspect | RFC 3164 (BSD) | RFC 5424 |
|---|---|---|
| Status | Informational, "as observed" | Standards Track |
| Timestamp | `Mmm dd hh:mm:ss` — **no year, no timezone, no sub-second** | RFC 3339 with timezone and fractional seconds |
| Hostname | Bare, may be an IP | FQDN / IP, `NILVALUE` allowed |
| Message size | 1024 bytes total | 2048 minimum, receivers may accept more |
| Structured data | None | `STRUCTURED-DATA` element (`[origin ip="…"][meta …]`) |
| App name / PID | Convention only (`tag[pid]:`) | Dedicated `APP-NAME`, `PROCID`, `MSGID` fields |
| Transports | UDP/514 | UDP (RFC 5426), TLS (RFC 5425), TCP framing (RFC 6587) |

The absent year and timezone in RFC 3164 is a genuine operational hazard: a relay in a different timezone from the origin produces logs that cannot be correlated without out-of-band knowledge. Always prefer RFC 5424 (`RSYSLOG_SyslogProtocol23Format`) or a custom RFC 3339 template when you control both ends.

## 3. `systemd-journald`: internals

### 3.1 What it actually is

`journald` is a structured, indexed, append-only binary log store. It ingests from:

- `/run/systemd/journal/dev-log` — the `/dev/log` compatibility socket
- `/run/systemd/journal/socket` — the native protocol (`sd_journal_send()`), which carries arbitrary key/value fields
- `/run/systemd/journal/stdout` — `stdout`/`stderr` of every unit
- `/dev/kmsg` — the kernel ring buffer
- the audit netlink socket, when `Audit=yes`

Every record is a set of fields. Fields whose names begin with `_` are **trusted**: they are appended by `journald` itself from the sender's credentials over `SO_PEERCRED`, and cannot be forged by the sending process. This is the single most important property of the journal and the reason it is not merely "a different log file".

| Field | Trusted? | Meaning |
|---|---|---|
| `MESSAGE` | No | Free text |
| `PRIORITY` | No | Severity 0–7 |
| `SYSLOG_FACILITY` | No | Facility number |
| `SYSLOG_IDENTIFIER` | No | Tag |
| `MESSAGE_ID` | No | 128-bit UUID identifying a *message type* |
| `_PID`, `_UID`, `_GID` | **Yes** | Kernel-verified sender credentials |
| `_COMM`, `_EXE`, `_CMDLINE` | **Yes** | Process identity |
| `_SYSTEMD_UNIT`, `_SYSTEMD_SLICE`, `_SYSTEMD_CGROUP` | **Yes** | cgroup-derived unit attribution |
| `_BOOT_ID`, `_MACHINE_ID`, `_HOSTNAME` | **Yes** | Host/boot identity |
| `_TRANSPORT` | **Yes** | `journal`, `stdout`, `syslog`, `kernel`, `audit`, `driver` |
| `__REALTIME_TIMESTAMP`, `__MONOTONIC_TIMESTAMP`, `__CURSOR` | **Yes** | Addressing/ordering |

### 3.2 Storage layout and the persistence decision

```
/run/log/journal/<machine-id>/system.journal          ← volatile (tmpfs, lost on reboot)
/var/log/journal/<machine-id>/system.journal          ← persistent, active
/var/log/journal/<machine-id>/system@<seq>-<ts>.journal  ← rotated, sealed
/var/log/journal/<machine-id>/user-1000.journal       ← per-UID split
```

`Storage=` semantics:

| Value | Behaviour |
|---|---|
| `volatile` | `/run/log/journal` only. Lost at reboot. |
| `persistent` | `/var/log/journal` created automatically if missing; falls back to `/run` until `/var` is mounted. |
| `auto` | **Default.** Persistent *only if `/var/log/journal/` already exists as a directory.* |
| `none` | Nothing stored; forwarding still works. Useful when rsyslog owns retention. |

> **The most common real-world surprise on Debian/Ubuntu-derived and minimal images:** `Storage=auto` plus a missing `/var/log/journal` directory means `journalctl -b -1` returns *"Specifying boot ID or boot offset has no effect, no persistent journal was found"*. The fix is `mkdir -p /var/log/journal && systemd-tmpfiles --create --prefix /var/log/journal && systemctl restart systemd-journald`, or `journalctl --flush`.

### 3.3 Disk accounting

Size limits apply **per journal namespace, per storage location**, and rotation is by file, not by record:

| Directive | Default | Notes |
|---|---|---|
| `SystemMaxUse=` | 10% of filesystem, capped at 4 GiB | Total across all persistent files |
| `SystemKeepFree=` | 15% of filesystem | Whichever limit is hit first wins |
| `SystemMaxFileSize=` | 1/8 of `SystemMaxUse=` | Individual file rotation trigger |
| `SystemMaxFiles=` | 100 | Count ceiling |
| `RuntimeMaxUse=` / `RuntimeKeepFree=` / … | Same rules for `/run` | `/run` is RAM — be conservative |
| `MaxRetentionSec=` | 0 (off) | Time-based expiry |
| `MaxFileSec=` | 1 month | Forces rotation even on idle systems |

### 3.4 Rate limiting — the field that silently eats your incident

```
RateLimitIntervalSec=30s
RateLimitBurst=10000
```

Beyond `RateLimitBurst` messages from *the same service* within the interval, `journald` drops and emits a `"Suppressed N messages from …"` marker. During an incident, the noisiest service is precisely the one being throttled. Override per unit rather than globally:

```ini
# /etc/systemd/system/payments-api.service.d/10-logging.conf
[Service]
LogRateLimitIntervalSec=0
LogRateLimitBurst=0
LogLevelMax=info
LogNamespace=payments
```

`LogRateLimitIntervalSec=0` disables limiting for that unit only. `LogNamespace=` spawns a dedicated `systemd-journald@payments.service` with its own storage and its own quota — the correct isolation primitive for a chatty tenant on a shared host.

## 4. `rsyslog`: architecture

`rsyslog` is a modular message router, not a log file writer. The pipeline is:

```
input module (im*) ─► parser ─► ruleset ─► [filter] ─► action queue ─► output module (om*)
                                    │
                                    └─► template (formats the outbound message)
```

### 4.1 Modules that matter

| Module | Role |
|---|---|
| `imuxsock` | Reads `/dev/log` (the AF_UNIX socket) |
| `imjournal` | Reads the systemd journal directly, preserving structured fields |
| `imklog` | Reads the kernel ring buffer |
| `imfile` | Tails plain files (`nginx`, application logs) into the pipeline |
| `imtcp` / `imudp` / `imrelp` | Network receivers |
| `impstats` | Emits rsyslog's own counters — mandatory for production |
| `omfwd` | Forwards over UDP/TCP (optionally TLS) |
| `omrelp` | Forwards over RELP (application-level ACK) |
| `omfile` | Writes files |
| `omprog` / `omhttp` / `omelasticsearch` | External sinks |

> **Duplication pitfall:** enabling **both** `imjournal` **and** `imuxsock` while `journald` has `ForwardToSyslog=yes` produces every message twice. Pick one ingestion path. The two coherent configurations are:
> - **journald-first:** `imjournal` only, and `SysSock.Use="off"` on `imuxsock`. Structured fields survive; slightly higher CPU.
> - **socket-first:** `imuxsock` only, `ForwardToSyslog=yes` in `journald.conf`. Cheaper; structured fields are flattened to RFC 3164 text.

### 4.2 Selector syntax (legacy, still examinable)

```
facility.priority            action
```

| Expression | Matches |
|---|---|
| `mail.info` | `mail` facility at `info` **and more severe** (info→emerg) |
| `mail.=info` | `mail` at exactly `info` |
| `mail.!=info` | `mail` at everything except `info` |
| `mail.!info` | `mail` at everything *less severe* than `info` |
| `*.info` | Every facility at `info` and above |
| `*.info;mail.none` | …except `mail`, which is excluded entirely |
| `auth,authpriv.*` | Both facilities, all severities |
| `*.emerg` | Everything at `emerg` |

Action targets:

| Action | Meaning |
|---|---|
| `/var/log/messages` | Write to file (sync) |
| `-/var/log/messages` | Write to file, **omit `fsync()`** — faster, loses tail on crash |
| `@192.0.2.10:514` | Forward over **UDP** |
| `@@192.0.2.10:514` | Forward over **TCP** |
| `:omrelp:192.0.2.10:2514` | Forward over RELP |
| `\|/var/run/some.pipe` | Named pipe |
| `/dev/console` | Console |
| `root,ops` | `wall`-style message to logged-in users |
| `*` | All logged-in users |
| `~` / `stop` | Discard — `stop` is the modern spelling |

> **Exam trap:** the difference between `@` (UDP) and `@@` (TCP), and the meaning of the leading `-` on a file path, are perennial questions. So is `mail.none`.

### 4.3 Delivery guarantees — the trade-off table

| Transport | Loss on network fault | Loss on receiver restart | Ordering | Cost | Use when |
|---|---|---|---|---|---|
| UDP (`@`) | Silent, total | Silent | None | Lowest | Never, in production, alone |
| TCP (`@@`) | Kernel buffer only; app-level loss on close | Messages in flight lost — TCP ACK ≠ written | FIFO per connection | Low | Intra-datacenter, non-audit |
| TCP + TLS | Same as TCP | Same as TCP | FIFO | Moderate (handshake, crypto) | Crossing untrusted networks |
| RELP (`omrelp`) | **None** — sender retransmits unacknowledged batches | **None** — ACK is issued after the receiver committed | FIFO | Moderate | Audit, compliance, financial |
| RELP + TLS | None | None | FIFO | Highest | Regulated multi-region |

Layered on top, the **queue** determines what happens when the action cannot proceed:

| Queue type | Backing | Survives restart | Throughput | Failure mode |
|---|---|---|---|---|
| `direct` | None | n/a | Highest | Blocks the ruleset — back-pressures producers |
| `FixedArray` | RAM, preallocated | No | High | Drops or blocks at `queue.highWatermark` |
| `LinkedList` | RAM, on demand | No | High | Same, lower memory floor |
| `Disk` | Spool files | Yes | Low | Bounded by `queue.maxDiskSpace` |
| **`LinkedList` + `queue.filename`** (*disk-assisted*) | RAM, spilling to disk | Yes (`queue.saveOnShutdown="on"`) | High | **The production answer** |

## 5. Comparative: journald vs rsyslog vs syslog-ng

| Dimension | `systemd-journald` | `rsyslog` | `syslog-ng` |
|---|---|---|---|
| Storage format | Binary, indexed, hash-chained | Plain text (or any sink) | Plain text (or any sink) |
| Structured fields | Native, with kernel-verified `_` fields | Via `imjournal`/JSON templates | Native name/value pairs |
| Query language | `journalctl FIELD=value`, `-p`, `--since` | `grep`/`awk` on files | `grep`/`awk` on files |
| Network transport | Only via `systemd-journal-upload`/`-remote` (HTTPS) | Rich: UDP/TCP/TLS/RELP/Kafka/HTTP | Rich, comparable |
| Guaranteed delivery | No (local only) | Yes, with RELP + disk queue | Yes, with disk buffer + flow control |
| Tamper evidence | **FSS** (Forward Secure Sealing) | None built in | None built in |
| Rotation | Built in (`SystemMaxUse=`) | External (`logrotate`) | External (`logrotate`) |
| Config language | INI | RainerScript (+ legacy selectors) | Declarative source/filter/destination |
| Per-service isolation | `LogNamespace=` | Rulesets | Multiple `log {}` paths |
| Availability | Every systemd distro | Default on RHEL/Debian/SUSE | Default on some appliances, common opt-in |
| CPU / message | Higher (indexing, hashing) | Low | Low |

**Architectural recommendation:** run **both**, with a clear division of responsibility. `journald` is the local, structured, tamper-evident buffer with a bounded footprint and no network exposure. `rsyslog` (or Vector/Fluent Bit) reads from it and owns the network hop and central retention. `Storage=` in `journald.conf` then becomes a deliberate choice about how much local forensic buffer you want after the network hop fails.

## 6. Complete configurations

### 6.1 `/etc/systemd/journald.conf` — production baseline

```ini
# /etc/systemd/journald.conf
# Local structured forensic buffer. Retention lives centrally; this is the
# window that survives a network partition.
[Journal]
Storage=persistent
Compress=yes
Seal=yes

# ---- disk accounting -------------------------------------------------------
SystemMaxUse=2G
SystemKeepFree=1G
SystemMaxFileSize=128M
SystemMaxFiles=32
MaxRetentionSec=14day
MaxFileSec=1day

# /run is RAM. Keep the volatile fallback small.
RuntimeMaxUse=128M
RuntimeKeepFree=256M
RuntimeMaxFileSize=16M

# ---- rate limiting ---------------------------------------------------------
# Global guardrail; chatty units get a per-unit override in a drop-in.
RateLimitIntervalSec=30s
RateLimitBurst=20000

# ---- forwarding ------------------------------------------------------------
# rsyslog ingests via imjournal, NOT via /run/systemd/journal/syslog.
ForwardToSyslog=no
ForwardToKMsg=no
ForwardToConsole=no
ForwardToWall=yes

# ---- level ceilings --------------------------------------------------------
MaxLevelStore=debug
MaxLevelSyslog=debug
MaxLevelKMsg=notice
MaxLevelConsole=emerg
MaxLevelWall=emerg

# ---- other -----------------------------------------------------------------
SplitMode=uid
Audit=no
LineMax=48K
```

Apply and verify:

```console
# systemctl restart systemd-journald
# systemd-analyze cat-config systemd/journald.conf | grep -E '^(Storage|Seal|SystemMaxUse)'
Storage=persistent
Seal=yes
SystemMaxUse=2G
```

### 6.2 Enabling Forward Secure Sealing

FSS makes retroactive tampering detectable: `journald` periodically seals the log with an evolving key; the *verification* key is printed once and must be stored off-host.

```console
# journalctl --setup-keys --interval=15min
Generating seed...
Generating key pair...
Generating sealing key...

The new key pair has been generated. The secret sealing key has been written to
the following local file. This key file is automatically updated when the
sealing key is advanced. It should not be used on multiple hosts.

	/var/log/journal/9f2c5c1b7a1e4d0e8b3f6a2d4c9e1b77/fss

Please write down the following secret verification key. It should be stored at
a safe location and should not be saved locally on disk.

	e1a3b9-2c7d40-88f1ae-30b562/1a2b3c-35a4e900

	The sealing key is automatically changed every 15min.

The keys have been generated for host web-01/9f2c5c1b7a1e4d0e8b3f6a2d4c9e1b77.
```

Verification later (`--verify-key` is the *verification* key printed above):

```console
# journalctl --verify --verify-key=e1a3b9-2c7d40-88f1ae-30b562/1a2b3c-35a4e900
PASS: /var/log/journal/9f2c.../system@0006213f.journal
PASS: /var/log/journal/9f2c.../system.journal
```

### 6.3 `/etc/rsyslog.conf` — leaf node, journald-first, disk-assisted RELP+TLS

```rsyslog
#### /etc/rsyslog.conf — leaf node ####
#### rsyslog 8.24+ / RainerScript syntax ####

#### GLOBAL DIRECTIVES ####
global(
  workDirectory="/var/spool/rsyslog"
  maxMessageSize="64k"
  defaultNetstreamDriver="gtls"
  defaultNetstreamDriverCAFile="/etc/pki/rsyslog/ca.pem"
  defaultNetstreamDriverCertFile="/etc/pki/rsyslog/web-01.pem"
  defaultNetstreamDriverKeyFile="/etc/pki/rsyslog/web-01.key"
)

module(load="builtin:omfile"
       fileOwner="root" fileGroup="adm"
       fileCreateMode="0640" dirCreateMode="0755")

#### INPUTS ####
# journald is the single ingestion path. Do NOT also read /dev/log.
module(load="imjournal"
       StateFile="/var/lib/rsyslog/imjournal.state"
       Ratelimit.Interval="0"          # journald already rate-limits
       Ratelimit.Burst="0"
       IgnorePreviousMessages="off"
       UsePid="system")

# Application files that never learned to use syslog.
module(load="imfile" mode="inotify")
input(type="imfile"
      File="/var/log/nginx/access.log"
      Tag="nginx-access"
      Severity="info"
      Facility="local6"
      PersistStateInterval="200"
      reopenOnTruncate="on"
      ruleset="ship")

input(type="imfile"
      File="/var/log/nginx/error.log"
      Tag="nginx-error"
      Severity="error"
      Facility="local6"
      PersistStateInterval="200"
      reopenOnTruncate="on"
      ruleset="ship")

# Self-monitoring: emit rsyslog's own counters every 60 s as JSON.
module(load="impstats"
       interval="60"
       severity="7"
       log.syslog="on"
       resetCounters="off"
       format="cee"
       ruleset="ship")

#### TEMPLATES ####
template(name="RFC5424Plus" type="list") {
  constant(value="<")   property(name="pri")
  constant(value=">1 ") property(name="timereported" dateFormat="rfc3339")
  constant(value=" ")   property(name="hostname")
  constant(value=" ")   property(name="app-name" caseConversion="lower")
  constant(value=" ")   property(name="procid")
  constant(value=" ")   property(name="msgid")
  constant(value=" [origin software=\"rsyslog\" swVersion=\"8\"]")
  constant(value=" ")   property(name="msg" droplastlf="on")
  constant(value="\n")
}

template(name="DynLocalPath" type="string"
         string="/var/log/remote/%HOSTNAME%/%$YEAR%-%$MONTH%-%$DAY%.log")

#### RULESET: local retention (short window) ####
ruleset(name="localfiles") {
  auth,authpriv.*                     action(type="omfile" file="/var/log/secure")
  *.info;mail.none;authpriv.none;cron.none
                                      action(type="omfile" file="/var/log/messages")
  mail.*                              action(type="omfile" file="/var/log/maillog")
  cron.*                              action(type="omfile" file="/var/log/cron")
  *.emerg                             action(type="omusrmsg" users="*")
  local7.*                            action(type="omfile" file="/var/log/boot.log")
}

#### RULESET: ship to the aggregator ####
ruleset(name="ship"
        queue.type="LinkedList"
        queue.size="200000"
        queue.dequeueBatchSize="1024"
        queue.workerThreads="2"
        queue.workerThreadMinimumMessages="20000") {

  action(type="omrelp"
         target="logs.internal.example.com"
         port="2514"
         tls="on"
         tls.caCert="/etc/pki/rsyslog/ca.pem"
         tls.myCert="/etc/pki/rsyslog/web-01.pem"
         tls.myPrivKey="/etc/pki/rsyslog/web-01.key"
         tls.authMode="name"
         tls.permittedPeer=["logs.internal.example.com"]
         template="RFC5424Plus"

         # ---- disk-assisted queue: survives restarts and outages ----
         queue.type="LinkedList"
         queue.filename="ship_relp"
         queue.spoolDirectory="/var/spool/rsyslog"
         queue.maxDiskSpace="4g"
         queue.maxFileSize="128m"
         queue.size="500000"
         queue.highWatermark="400000"
         queue.lowWatermark="200000"
         queue.discardMark="480000"
         queue.discardSeverity="6"     # shed info/debug before err/crit
         queue.saveOnShutdown="on"
         queue.timeoutShutdown="10000"
         queue.checkpointInterval="1000"

         # ---- never give up on the remote side ----
         action.resumeRetryCount="-1"
         action.resumeInterval="10"
         action.reportSuspension="on")
}

#### MAIN ####
*.* call localfiles
*.* call ship
```

### 6.4 Central collector `/etc/rsyslog.d/10-collector.conf`

```rsyslog
#### Central aggregator: RELP over TLS in, per-host files out ####

module(load="imrelp"
       ruleset="fromremote")
input(type="imrelp"
      port="2514"
      tls="on"
      tls.caCert="/etc/pki/rsyslog/ca.pem"
      tls.myCert="/etc/pki/rsyslog/logs.pem"
      tls.myPrivKey="/etc/pki/rsyslog/logs.key"
      tls.authMode="name"
      tls.permittedPeer=["*.internal.example.com"]
      maxDataSize="64k")

# Legacy appliances that only speak UDP — firewalled to a management VLAN.
module(load="imudp" threads="2" timeRequery="8")
input(type="imudp" port="514" address="10.20.0.5" ruleset="fromremote")

template(name="PerHostFile" type="string"
         string="/srv/logs/%$YEAR%/%$MONTH%/%$DAY%/%FROMHOST-IP%/%PROGRAMNAME%.log")

ruleset(name="fromremote"
        queue.type="LinkedList"
        queue.filename="q_fromremote"
        queue.spoolDirectory="/var/spool/rsyslog"
        queue.maxDiskSpace="16g"
        queue.saveOnShutdown="on"
        queue.size="1000000") {

  # Drop anything whose hostname we do not recognise, before it costs disk.
  if not ($fromhost-ip startswith "10.20.") then {
      stop
  }

  action(type="omfile"
         dynaFile="PerHostFile"
         dynaFileCacheSize="200"
         template="RSYSLOG_FileFormat"
         ioBufferSize="64k"
         flushOnTXEnd="off"
         asyncWriting="on"
         fileOwner="root" fileGroup="adm" fileCreateMode="0640")
}
```

**Directive reference:**

| Directive | Effect |
|---|---|
| `daily` / `weekly` / `monthly` / `yearly` | Time-based trigger |
| `size 100M` | Rotate when larger — **overrides** time-based scheduling |
| `maxsize 100M` | Rotate at the scheduled time **or** earlier if larger |
| `minsize 1M` | Rotate at the scheduled time **only if** larger |
| `rotate N` | Keep N generations |
| `maxage N` | Delete rotated logs older than N days |
| `compress` / `nocompress` | gzip (or `compresscmd`) rotated files |
| `delaycompress` | Compress on the *next* run — required when the writer keeps the fd open |
| `missingok` | No error if the file is absent |
| `notifempty` / `ifempty` | Skip / allow rotating an empty file |
| `create MODE OWNER GROUP` | Recreate the file after rename |
| `copytruncate` | Copy then truncate in place — **inode preserved** |
| `dateext` / `dateformat` | Suffix with a date instead of `.1`, `.2` |
| `olddir` / `createolddir` | Move rotated files elsewhere |
| `sharedscripts` | Run `pre/postrotate` **once** for the whole glob, not per file |
| `su USER GROUP` | Drop privileges while rotating a group-writable directory |
| `prerotate` / `postrotate` … `endscript` | Hooks; the log name is `$1` unless `sharedscripts` |
| `firstaction` / `lastaction` | Run once before/after everything in the block |

**`create` vs `copytruncate` — the decision that breaks production:**

| | `create` (rename + recreate) | `copytruncate` |
|---|---|---|
| Mechanism | `rename()` old → new name, create fresh file | `cp` contents, then `truncate()` the original |
| Inode | Changes | Preserved |
| Writer must | Reopen the file (`SIGHUP`/`SIGUSR1`) or it keeps writing to the rotated inode | Nothing |
| Data loss window | None | **Yes** — writes between `cp` and `truncate()` are lost |
| Disk spike | None | 2× the file size during the copy |
| Use when | The application supports reopen (nginx, rsyslog, httpd) | The application cannot reopen and cannot be patched |

`copytruncate` also breaks `O_APPEND` writers less than you would think but breaks `imfile` state tracking more than you would think — hence `reopenOnTruncate="on"` in the leaf configuration above.

### 7.2 `journalctl` in anger

```console
# Follow a unit, with microsecond timestamps
$ journalctl -u nginx.service -f -o short-precise
```

If step 4 fails but step 3 succeeds, the fault is in the network hop; if step 3 fails but step 2 succeeds, it is in `rsyslog`; if step 2 fails, it is in `journald` or the socket.

### 9.2 Symptom → cause → verification

| Symptom | Likely cause | Command that proves it |
|---|---|---|
| `journalctl -b -1` says "no persistent journal" | `Storage=auto` and `/var/log/journal` missing | `ls -ld /var/log/journal; systemd-analyze cat-config systemd/journald.conf \| grep ^Storage` |
| Messages appear twice in `/var/log/messages` | `imjournal` **and** `imuxsock` both active, or `ForwardToSyslog=yes` alongside `imjournal` | `grep -rE 'imjournal\|imuxsock\|SysSock' /etc/rsyslog.conf /etc/rsyslog.d/`; `grep ForwardToSyslog /etc/systemd/journald.conf` |
| "Suppressed N messages from …" in the journal | journald rate limit | `journalctl -u systemd-journald -g Suppressed`; fix with `LogRateLimitBurst=` drop-in |
| Nothing arrives at the collector, no error locally | UDP action + firewall drop | `ss -lunp \| grep 514` on the collector; `tcpdump -ni eth0 udp port 514` |
| rsyslog logs "action suspended" repeatedly | Remote unreachable or TLS peer rejected | `journalctl -u rsyslog -g suspended -n 20`; `openssl s_client -connect logs:2514 -CAfile /etc/pki/rsyslog/ca.pem` |
| Disk queue grows without bound | `queue.maxDiskSpace` unset or too large; downstream down | `du -sh /var/spool/rsyslog`; impstats `size`/`maxqsize` |
| Log file rotated but keeps growing under the old name | Writer holds the fd and no `postrotate` reopen signal | `sudo lsof -p $(pidof nginx \| cut -d' ' -f1) \| grep '\.log'` → look for `(deleted)` |
| `logrotate` "does nothing" | Stale state file, or `notifempty` with an empty log, or bad file permissions | `logrotate --debug /etc/logrotate.conf`; `grep messages /var/lib/logrotate/logrotate.status` |
| logrotate: "Ignoring … because of bad file mode / bad owner" | Directory or file writable by a non-root owner and `su` not declared | Add `su root adm`; `stat -c '%A %U:%G' /var/log/nginx` |
| `/var` full despite rotation | Journal not counted in the rotation budget | `journalctl --disk-usage`; `du -sh /var/log/* \| sort -h \| tail` |
| Timestamps in the central store are hours off | RFC 3164 has no timezone; relay in another TZ | Switch the template to `RSYSLOG_SyslogProtocol23Format` / RFC 3339 |
| Journal reports corruption after a crash | Unclean shutdown mid-write | `journalctl --verify`; rotate away the bad file with `journalctl --rotate` |

### 9.3 Proving the file-descriptor rotation bug

The single most common "logs stopped" incident. After rotation, an application that never reopened keeps writing to the unlinked inode:

```console
$ sudo lsof -p 2291 | grep -E 'access\.log'
nginx   2291 nginx    5w   REG  253,1  1073741824  132876 /var/log/nginx/access.log-20260827 (deleted)

$ ls -l /var/log/nginx/access.log
-rw-r----- 1 nginx adm 0 Aug 27 00:00 /var/log/nginx/access.log

$ df -h /var
Filesystem      Size  Used Avail Use% Mounted on
/dev/mapper/vg-var   20G   19G  1.0G  95% /var
```

The new file is 0 bytes, the deleted inode is 1 GiB and still growing, and the space is not reclaimed until the process closes the fd. Resolution: send the reopen signal (`kill -USR1` for nginx, `systemctl reload rsyslog`, `SIGHUP` for most daemons) and add the `postrotate` block permanently.

### 9.4 Disk pressure runbook

```console
# Immediate reclamation, ordered from safest to most destructive
$ sudo journalctl --vacuum-time=2d
Deleted archived journal /var/log/journal/9f2c.../system@0006213f-...journal (128.0M).
Vacuuming done, freed 768.0M of archived journals from /var/log/journal/9f2c...

$ sudo journalctl --vacuum-size=500M
$ sudo journalctl --rotate && sudo journalctl --vacuum-files=5

# Force a rotation cycle across everything logrotate manages
$ sudo logrotate -f /etc/logrotate.conf

# Find the actual consumer — remember deleted-but-open files
$ sudo du -xh --max-depth=2 /var/log | sort -h | tail -10
$ sudo lsof -nP +L1 /var | awk '$7 > 100000000'
```

Make the limits permanent afterwards (`SystemMaxUse=`, `maxsize`, `maxage`) — a manual vacuum that is not followed by a configuration change guarantees the same page at the same hour next month.

## 10. Exam-focused checklist

- `PRI = facility × 8 + severity`; `authpriv` is 10, `local0`–`local7` are 16–23; `emerg`=0 … `debug`=7.
- `mail.info` means info **and above**; `mail.=info` is exact; `mail.none` excludes.
- `@host` is UDP, `@@host` is TCP; a `-` before a filename skips `fsync()`.
- `rsyslogd -N1` validates configuration without restarting.
- `logger -p local0.err -t mytag "msg"` — default priority is `user.notice`.
- `systemd-cat` wraps a command; `logger --journald` sends native fields.
- `journalctl -u`, `-b`, `-k`, `-p`, `-f`, `--since`, `--disk-usage`, `--vacuum-size`, `--verify`.
- Persistent journal requires `/var/log/journal` to exist (or `Storage=persistent`).
- `logrotate` is driven by `/etc/logrotate.conf` + `/etc/logrotate.d/`, scheduled by `logrotate.timer` (or `cron.daily`), and remembers state in `/var/lib/logrotate/`.
- `copytruncate` preserves the inode and loses a small window; `create` + a `postrotate` reopen signal loses nothing.
- `sharedscripts` runs `postrotate` once per block instead of once per matched file.
- `/var/log/wtmp`, `btmp`, `lastlog` and the journal are **binary** — `cat` is never the answer.
