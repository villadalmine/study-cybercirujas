# Developers — use the API, run your own copy, build on it

Everything here is open: the code, the pipeline, and the study material. You
can query the API, run the whole platform yourself, fork it into something
different, or take the corpus and build your own thing. This page is how.

**Read the two disclaimers first.** They are not boilerplate: one is about
availability, the other is about what this material *is*.

## ⚠️ The API is beta, and hosted on a home cluster

`https://study.cybercirujas.club` runs on the owner's hardware as a personal
project. Concretely, and honestly:

- **No uptime guarantee.** It goes down when the house does. Expect timeouts,
  cold starts after a deploy (the first `/api/status` call rebuilds a cache and
  can take a few seconds), and occasional 502s during a rollout.
- **No rate limiting today**, which means no protection either — if it starts
  being hammered, the answer will be a limit, not more capacity. Be reasonable:
  cache what you fetch, and do not poll what does not change.
- **No versioning yet.** Paths and payloads can change. Watch
  [CHANGELOG.md](CHANGELOG.md); breaking changes are recorded there.
- **No authentication** on the public endpoints, and none planned — the content
  is free by decision, not by oversight.
- **If you need reliability, run your own copy.** That is what the rest of this
  page is for, and it is a supported path rather than a consolation prize.

## ⚠️ The content is AI-generated — and that carries real risk

Every topic on this platform was written by a large language model from an
official exam syllabus. Nothing is human-authored. That is disclosed under
[EU AI Act Article 50](https://artificialintelligenceact.eu/article/50/) and it
means something practical for you:

- Material passes a **quality floor** and mechanical checks (citations resolve,
  embedded manifests parse, no removed Kubernetes APIs), and every topic
  records the model, date and source document that produced it.
- **What no check proves is that an explanation is true.** A confident, well
  cited, wrong paragraph passes everything above — the gap is documented at
  [docs/AUDITOR_DESIGN.md](docs/AUDITOR_DESIGN.md).
- **If you redistribute this material, that risk travels with it**, and the
  Article 50 disclosure obligation travels with it too. Keep the provenance:
  every `meta.yaml` names the model and the vendor document, and the API
  returns it in `generated_by` for exactly this reason.

Treat it as a study aid whose authority is the official documentation it cites,
and say so to your own users.

## Using the hosted API

Base URL `https://study.cybercirujas.club`. Everything is JSON, `GET`, no key.

Interactive reference, generated from the running application and therefore
never out of date: **`/docs`** (Swagger UI) and **`/openapi.json`** (the raw
schema — point a client generator at it).

|---|---|---|

| `GET` | `/api/certs/{cert_id}` | One certification: catalogue entry, syllabus and which topics have material |
| `GET` | `/api/certs/{cert_id}/topics/{topic_id}` | A topic's material: content, exercises, lab, and the provenance of what is served |

Language is a query parameter (`?lang=es`) on topic endpoints; `/api/langs`
lists what exists. A topic falls back through `en → es` when your language is
missing, and says so in `lang_fallback` rather than pretending.

```bash
# every certification, with vendor, level, validity and official sources
curl -s https://study.cybercirujas.club/api/catalog | jq 'keys'

# one topic's material, in Spanish, with provenance
curl -s 'https://study.cybercirujas.club/api/certs/cks/topics/1.1?lang=es' \
  | jq '{lang, generated_by, chars: (.content|length)}'

# what is complete, which exam version it was built on, when it was checked
curl -s https://study.cybercirujas.club/api/status | jq '.[] | select(.state=="outdated")'
```

## Running your own copy

```bash
git clone https://github.com/villadalmine/study-cybercirujas.git
cd study-cybercirujas
make setup      # venv, CLI, and the pre-commit hook
make serve      # API + web on http://127.0.0.1:8000
```

That is the whole platform: the same FastAPI app and single-page frontend that
runs in production, serving the markdown in `certs/` straight from disk. There
is no database and no build step for the site.

**Just the API**, without the frontend, as a library or a service:

```bash
.venv/bin/uvicorn teach.api:app --host 0.0.0.0 --port 8000
```

**In Kubernetes**, with the chart used in production:

```bash
make image-cluster TAG=mine        # build in-cluster with Kaniko
make deploy-local TAG=mine         # helm upgrade --install
```

Pass the **same explicit `TAG`** to both: it defaults to a fresh timestamp per
invocation, so omitting it deploys a tag you did not build. The chart is at
`deploy/helm/`; `values.yaml` documents every knob, including the weekly
model-check CronJob.

**Using the corpus without any of our code** — it is markdown on disk, laid out
predictably:

```
certs/<cert>.md                       syllabus: objectives, weights, status
certs/<cert>/<topic>/<lang>/content.md
certs/<cert>/<topic>/<lang>/exercises.md
certs/<cert>/<topic>/<lang>/meta.yaml provenance: model, date, sources
certs/<cert>/<topic>/lab/             break-and-fix lab
```

## Staying in sync with upstream

The material keeps growing. Your copy can follow it without losing your work:

```bash
git remote add upstream https://github.com/villadalmine/study-cybercirujas.git
git fetch upstream
git merge upstream/main            # or: git rebase upstream/main
```

Content merges cleanly in practice because topics are separate files and are
only rewritten when regenerated. **Conflicts you can expect**: `STATUS.md`,
`MODELS.md` and `graphify-out/` are all generated — resolve them by
regenerating rather than by merging:

```bash
teach status                       # rewrites STATUS.md and MODELS.md from disk
make graph                         # rewrites the code graph
```

**Taking only the content**, if you have your own application: sparse-checkout
gives you `certs/` and nothing else, and `git pull` keeps it current.

```bash
git clone --filter=blob:none --sparse https://github.com/villadalmine/study-cybercirujas.git
cd study-cybercirujas && git sparse-checkout set certs catalog.yaml
```

## Building features on it

The design rule this project follows, and which makes it extensible: **state
lives in files, and every report is derived from them.** No hidden database, no
service to reverse-engineer.

- **The catalogue is `catalog.yaml`** — add a certification with
  `teach cert add`, point it at an official objectives document, and
  `teach cert snapshot` freezes the syllabus. Nothing else needs editing.
- **What the pipeline should produce is `pipeline.yaml`** — languages, quality
  floor, budget, which model authors, per-certification ownership. Change a
  decision there, not in a script.
- **Generation is backend-agnostic.** Every backend satisfies
  `complete(system, user) -> str`: `claude`, `litellm` (anything
  OpenAI-compatible, including local models), `codex`, `gemini`, or your own
  command via `TEACH_AGENT_CMD`. A certification can be started with one and
  finished with another.
- **The checks are the contract.** `make verify` runs the whole ladder for
  free; each check exists because something broke once, and each explains why
  in its own header. Add yours next to them.
- **The study bot is client-side** — the page calls OpenRouter with the
  student's key. Point it at another provider by editing one adapter; the model
  catalogue itself is data (`models.yaml`, served at `/api/models`).

## The lifecycle, and how to measure it

This repository is run as a DevOps loop, and the instrumentation is part of the
product rather than an afterthought. If you fork it, you inherit all of it.

**Culture** — decisions and their reasoning live in the repository, not in
someone's memory: [ROADMAP.md](ROADMAP.md) for where things are going,
[CHANGELOG.md](CHANGELOG.md) for what happened, [AGENTS_SYNC.md](AGENTS_SYNC.md)
for coordination between the humans and agents working on it. Every rule that
exists because something broke says what it cost.

**Automation** — one command per intent: `make next` decides what to work on,
`make milestone` works a goal to completion, `make verify` proves it,
`make check-updates` compares every frozen syllabus against what its vendor
publishes today. A pre-commit hook refuses commits that break the four fixed
rules, and it runs in under a second.

**Lean** — work is bounded on purpose: `budget.topics_per_run` caps a pass,
a declared milestone bounds unattended work, and no milestone means nothing is
generated. Small batches, resumable, idempotent.

**Measurement** — everything spent is recorded per completion and reported:

```bash
make metrics              # tokens and quota windows, per stage and per day
make status               # what is missing, unsound, in flight, and what it cost
scripts/topic_cost.py --forecast 40    # what the next N topics will take
curl -s localhost:8000/api/status      # the same truth the site serves
```

**Sharing** — this page, the open licence, and an API that returns provenance
so anything built on it can carry the disclosure forward.

### DORA, concretely

| Metric | Where it is visible | Current shape |
|---|---|---|
| **Deployment frequency** | `published.json` and the image tags — one deploy per completed certification, plus feature deploys | Several per week when content is being generated |
| **Lead time for changes** | commit → `make publish-complete` → rollout; the whole path is one command and a few minutes | Minutes for code, hours-to-days for a certification (bounded by quota, not process) |
| **Change failure rate** | `make verify` before publishing, the pre-commit hook, and the fact that nothing partial can reach `published.json` — completeness is derived from the tree | Failures that do occur are caught at build or verify, not by students |
| **Time to restore** | `make deploy-local TAG=<previous>` — every image is a tag, rollback is one command | Minutes |

**Contributing**: every push and pull request runs the free half of
`make verify` in GitHub Actions (`.github/workflows/verify.yml`) — quality
floor, manifests, Kubernetes APIs, provenance, sources, syllabus coverage,
the STATUS.md and API-reference freshness checks, the tests, and a secret
scan. No quota is spent, so a stranger's pull request gets the same verdict
the owner gets. Three checks are excluded because they describe the
workstation rather than the commit: `check_units` reads installed systemd
units, `check_config` compares against local usage records, and
`status_matrix --check` counts rendered videos, which are gitignored for
size and therefore absent from any clean checkout.

Where the loop is honest about its gaps: publishing is a manual step (the
workstation running the unattended pass has no `make`/`kubectl`/`helm`) and
the registry has no retention policy. Both are in [ROADMAP.md](ROADMAP.md).
